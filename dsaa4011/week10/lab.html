Keep image details while regularising the hidden code

An image encoder produces a smaller hidden code. Its decoder must use that code to rebuild the original image's details.

Training requirementIn plain words
Reconstruction qualityKeep enough image information for the decoder
Prior penalty KL(q(z∣x)∥p(z))\mathrm{KL}(q(z\mid x)\|p(z))KL(q(z∣x)∥p(z))Keep each guessed code distribution near the prior
Weight the two requirementsDecide how strongly to regularise while preserving useful details
A simplified weighted objective: reconstruction reward−β KL(q(z∣x)∥p(z))\text{reconstruction reward}-\beta\,\mathrm{KL}(q(z\mid x)\|p(z))reconstruction reward−βKL(q(z∣x)∥p(z)). Here β\betaβ sets the penalty weight.

If every image produced the same code distribution, the code would not distinguish their details. A weaker penalty may help retain information; it is not a guarantee. Image systems can also use perceptual and adversarial losses.

SoImage autoencoders balance useful reconstruction and latent regularisation. A modified loss need not be the original lower bound L\mathcal LL.NextWhere else do we reuse a learned function to infer hidden information?

Check: can the decoder recover discarded details?

Two original pictures produce exactly the same code. No other information reaches the decoder.

Can a deterministic decoder reconstruct both originals exactly?
Answer. No. It can choose or invent a reconstruction, but cannot know which of the two originals produced that code.
SoA downstream model cannot identify information the code does not distinguish.NextWhat should we measure when judging a latent system?
